## 3) Source Code (src)

### src/feature_groups.py
Purpose:
- Defines the canonical feature schema for this dataset variant (39 features + Label).
- Stores feature typing and mutability groupings used by validator and preprocessing.
- Stores class-to-category mapping for 34 classes -> 8 categories.

Key contents:
- FEATURE_NAMES: 39 model features
- LABEL_COLUMN: Label
- EXPECTED_COLUMNS: feature list + label for schema reconciliation
- BINARY_FEATURES, INTEGER_FEATURES, MUTABLE_FEATURES
- CATEGORY_MAP
- PERTURBATION_MASK base mask for mutable features

Notes:
- Includes IGMP and Time_To_Live (dataset-specific extras vs canonical schema A/B).

### src/validator.py
Purpose:
- Implements feature-space validity checks for cleaned, unscaled data.

Key checks:
- Non-negativity rules
- Protocol-type validity and protocol/indicator consistency
- Binary flag validation
- Min <= AVG <= Max consistency
- Variance approx Std^2 tolerance rule
- TTL range check [0,255]
- Packet-count positivity/integer checks

Outputs:
- ValidationResult object with per-rule and overall validity metrics.

### src/eda_tables.py
Purpose:
- Generates thesis tables T1-T5 from data/processed/raw_loaded.parquet.

Outputs:
- T1 feature schema with descriptions and summary stats
- T2a per-class counts, T2b per-category counts
- T3 distributional statistics, skew, kurtosis, sparsity proxies
- T4 clean-data validity audit from validator
- T5 sampled rows (wide CSV and transposed markdown)
- data/processed/class_to_category.json
- data/processed/clean_data_validity_report.json

### src/eda_figures_part1.py
Purpose:
- Generates F1-F3.

Outputs:
- F1 class/category imbalance bar plots
- F2 feature overlays as log-binned histograms with shared per-feature ranges across classes
- F3 absolute Spearman correlation heatmap
- tables/F3_correlation_matrix.csv

### src/netdiffuser_categorization.py
Purpose:
- Implements NetDiffuser-style feature partitioning into Discrete vs Relative.

Current selection logic:
- Builds CH-score curve over cut heights in [0.1, 1.0] with 100 points
- Prefers local CH maxima satisfying non-trivial clustering:
  - at least 3 clusters with size >= 2 features

Outputs returned by function:
- discrete, relative lists
- linkage matrix
- best_cut, best_index, best_is_nontrivial
- h_grid, ch_scores, nontrivial_flags, correlation_matrix

### src/eda_figures_part2.py
Purpose:
- Generates F4-F7 and T6.

Outputs:
- F4a PCA projection
- F4b PCA loadings bar charts
- F5 t-SNE projection
- F6b UMAP (Benign vs Mirai focus)
- F7a NetDiffuser dendrogram
- F7b CH-score vs cut-height curve
- tables/F4_pca_loadings.csv
- tables/T6_feature_categorization.csv/.md
- data/processed/tsne_coords.npz
- data/processed/umap_coords.npz
- data/processed/netdiffuser_categorization.json

Note about F6 global UMAP:
- Global F6 is saved to figures/appendix/F6_umap_by_category.pdf and removed from main figures/
  to keep core narrative focused on F5 and F6b.

### src/preprocessing.py
Purpose:
- Runs Phase 4 preprocessing and serializes training artifacts.

Main steps:
- Load data/processed/raw_loaded.parquet
- Clean/clip features and normalize integer/binary columns
- Encode labels (34-class, 8-category, binary)
- Stratified split 70/10/20
- Fit RobustScaler on train only
- Save arrays, class weights, perturbation mask
- Save content hashes and run manifest

Primary outputs:
- data/processed/X_*.npy and y_*.npy
- data/processed/scaler.pkl, label_encoder.pkl, category_encoder.pkl
- data/processed/class_weights_*.npy and class_weights_named.json
- data/processed/content_hashes.json
- config/run_manifest.json

## 12) Validator Rationale (Thesis Note)

This project validates CICIoT2023 in two stages and reports both numbers:

- Pre-clean validity:
  - Source: [data/processed/clean_data_validity_report.json](data/processed/clean_data_validity_report.json)
  - Meaning: how well raw loaded data conforms to the semantic rule set before Phase 4 cleaning.

- Post-clean validity:
  - Source: [data/processed/processed_data_validity_report.json](data/processed/processed_data_validity_report.json)
  - Meaning: whether the final preprocessed dataset used for modeling satisfies constraints after clipping/rounding and final checks.

Protocol-type rule clarification:

- The validator allowlist in [src/validator.py](src/validator.py) is:
  - {0, 1, 2, 6, 17, 47}
- Rationale:
  - 0 = HOPOPT
  - 1 = ICMP
  - 2 = IGMP
  - 6 = TCP
  - 17 = UDP
  - 47 = GRE (relevant to Mirai GREIP/GREETH attack families)

Protocol-indicator consistency policy:

- Implemented as indicator-implies-protocol constraints (robust direction):
  - if TCP=1 then Protocol Type must be 6
  - if UDP=1 then Protocol Type must be 17
  - if ICMP=1 then Protocol Type must be 1
  - if IGMP=1 then Protocol Type must be 2
- This avoids over-penalizing rows where indicator channels are not strict one-hot mirrors of Protocol Type in this release.

Recommended thesis wording:

- Pre-clean validity supports that the rules are semantically appropriate for the raw release.
- Post-clean validity supports that preprocessing produced a constraint-satisfying modeling dataset.
- Report both values explicitly in methodology to separate dataset quality from preprocessing correctness.
